# 카드 조합 확률 개편 · 2026-10-27

메인 메뉴의 **카드팩 → 카드 조합 → MY RKBO** 순서로 조합을 독립 배치했다. 카드팩 내부 조합 탭을 제거하고, 비로그인 첫 방문의 자동 로그인 안내가 열린 조합 창을 덮지 않도록 보완했다. 변경된 JS/CSS 네 파일의 로딩 버전은 `combo-v2-20261027`이다.

## 설계 근거와 공개 자료

- [넷마블 마구마구 공식 조합 확률표](https://sgimage.netmarble.com/web/netmarble/probabilitypage/html/ma9/10647/files/sheet007.html): 재료 등급 구성, 3장/5장, 일반/행운/보존권에 따라 확률을 구분한다. 같은 등급의 재료를 더 투입하면 상위 획득 기대가 높아지는 구조와 보존의 중요성을 참고했다.
- [컴투스프로야구V 공식 조합 업데이트 안내](https://cpbv-community.com2us.com/board/3/20487): 3~5장으로 1장 획득, 시도 전 확률 공개, 최고 재료를 기준으로 하는 별도의 등급 보호 기능을 설명한다. 손실 위험을 명확하게 공개하고 보존을 강화하는 설계 원칙을 참고했다.

아래 수치는 다른 게임의 확률을 복사한 값이 아닌 **RKBO 자체 밸런스**다. 별도 유료 보호권이나 신규 천장은 도입하지 않는다.

## 같은 등급 재료의 기준 확률

표의 순서는 **하락 / 같은 등급 보존 / 상위 등급**, 단위는 %다. 특수카드가 등록된 60차의 값이다.

| 재료 등급 | 3장 | 4장 | 5장 |
| --- | --- | --- | --- |
| 브론즈 | 0 / 65 / 35 | 0 / 55 / 45 | 0 / 45 / 55 |
| 실버 | 30 / 50 / 20 | 20 / 50 / 30 | 10 / 50 / 40 |
| 골드 | 30 / 55 / 15 | 20 / 58 / 22 | 10 / 60 / 30 |
| 코랄 | 30 / 60 / 10 | 20 / 64 / 16 | **10 / 68 / 22** |
| 다이아몬드 | 30 / 67 / 3 | 20 / 74 / 6 | 10 / 80 / 10 |

코랄 5장은 기존 **하락 64.5 / 보존 24.5 / 상위 11**에서 **10 / 68 / 22**로 바뀐다. 60차는 골드 10%, 코랄 68%, 다이아몬드 19%, 특수 3%다. 특수가 없는 1~59차는 다이아몬드 22%다. 보존은 재료 전부를 반환하는 뜻이 아니라 **같은 등급의 새로운 카드 1장** 획득이다.

## 혼합 재료와 시즌별 카드풀

기존 재료 점수(브론즈 1, 실버 3, 골드 7, 코랄 15, 다이아몬드 30)는 유지한다. 각 등급의 3·4·5장에 해당하는 15개 총점 기준점 사이를 선형 보간한다. 같은 총점에는 같은 기본 확률을 적용한다. 낮은 등급을 섞으면 최고 재료의 보존율은 동등급 재료만 썼을 때보다 낮을 수 있다.

재료 추가 또는 등급 상향으로 총점이 올라갈 때, 모든 등급 경계에서 '그 등급 이상' 확률이 낮아지지 않도록 설계했다. 같은 등급의 5장 조합은 실버~다이아몬드 모두 하락 10%이며, 고등급일수록 보존 비중이 커진다.

결과 후보가 없는 등급의 몫은 가장 가까운 등록 하위 등급에 합산한다. 하위가 하나도 없으면 최저 등록 등급으로 합산한다. 따라서 특수가 없는 시즌에서는 특수 확률이 다이아몬드로 이동하며, 보존 확률을 훼손하는 전체 재정규화는 하지 않는다. 59차의 브론즈 부재도 같은 규칙으로 처리한다. 카드풀과 카드팩 활성화 설정은 변경하지 않았다.

동일 시즌 재료는 해당 시즌, 혼합 시즌은 등록된 1~60차를 균등하게 선택한다. 견적 RPC는 각 시즌의 실제 등급 확률을 균등 평균해 반환한다. 내부 합산 중에는 반올림하지 않고, 최종 한 번만 소수점 6자리로 반올림해 합계를 정확히 100%로 맞춘다. 추첨은 같은 함수의 백만분의 1% 단위를 사용한다. 조합 응답 및 기록에는 전체 견적 `odds`, 선택 시즌의 `seasonOdds`, `balanceVersion`을 남겨 비교할 수 있다.

## 서버 반영과 보존 범위

운영 Supabase 프로젝트 `stajnaagugudgsabntuq`에 `card_combination_balance_v2` 마이그레이션을 적용했다. 변경 함수는 다음 세 개다.

- `rkbo_private.combo_rates(integer,integer)`
- `public.rkbo_combo_quote(text[])`
- `public.rkbo_combine_cards(text[],uuid)`

신규 설치용 `supabase/card-combination-system.sql`과 기존 설치용 `supabase/card-combination-balance-v2.sql`의 해당 함수 본문이 일치한다. 기존 인증, 재료 검사, 행 잠금, 요청 UUID 중복 방지, 원자적 차감·지급 구조를 유지했다.

적용 전후 14개 보호 범주의 해시 비교 결과 차이가 없었다: 조합 외 함수, 테이블 권한과 RLS, 함수 권한, 보유 카드, 강화 기록, MY TEAM, 저장된 드래프트 팀, 카드팩 상태·천장, 카드팩 기록, 조합 기록, 팩 활성화 설정, 카드 카탈로그, 특수카드 등록. 정규 카드팩의 46.5 / 31.5 / 15 / 5 / 1 / 1%와 50팩 천장은 그대로다.

- 운영 SQL `supabase/test-card-combination-rates-v2.sql`: 60시즌 × 148총점 = **8,880개 분포**, 합계/음수 오류 0, 등급별 누적확률 역전 0.
- 운영 SQL `supabase/test-card-combination-balance-v2.sql`: 1·59·60차의 동등급 3~5장 **42개 레시피**, 혼합 시즌 **1개 레시피**에서 실제 견적·조합 RPC 호출. 차감량 n장, 지급 1장, 동일 시즌 결과, 결과 등급의 양수 확률, 견적/추첨 확률 일치를 확인했다.
- 동일 요청 UUID **42회 재전송**에서 같은 결과 반환 및 추가 차감/기록 없음 확인.
- 마지막 1장, 금테, 프리즘, MY TEAM 편성 카드, 특수카드, 미보유 카드, 장수 범위, NULL 재료 차단 확인.
- `authenticated` 실제 역할로 RPC를 실행하고 다른 계정의 인벤토리·조합 기록·팀 접근 차단과 비로그인/익명 인증 거부를 확인했다. 내부 함수 직접 실행과 재료/기록 직접 쓰기 권한은 열지 않았다.
- 모든 계정·카드·팀 테스트 데이터는 한 트랜잭션에서 **ROLLBACK**했다. 테스트 후 보호 범주 해시가 전부 일치했다.
- 실제 사이트의 주변 자료를 읽고 수정 파일을 끼운 브라우저 검사: 메뉴 순서, 독립 열기, 비로그인 안내, 후보 검색·등급 필터, 3/4/5장 확률 표시, 5장 및 중복 수량 제한, 3장 미만 버튼 비활성, 카드팩 탭 제거, PC 1440×1000 및 모바일 390×844/320px 폭 확인. 인벤토리·견적만 테스트 응답으로 대체했으며 실제 카드는 소모하지 않았다. 페이지 JS 오류 0건. 화면 캡처로 PC·모바일 배치를 확인했다.
- Supabase 보안 Advisor 재점검: 이번 변경으로 추가된 항목 없음. 기존 로그인 RPC의 SECURITY DEFINER 안내 등은 변경 전과 동일하다. 조합 RPC는 의도된 로그인 전용 진입점이며 직접 호출 권한 및 소유권 차단을 별도로 검사했다.
