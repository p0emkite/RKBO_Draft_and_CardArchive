# RKBO Draft & Card Archive

**60차 시즌 카드 도감** — 8개 구단 1군 선수 중 타자 50경기 이상·투수 25경기 이상만 수록하는 시즌 카드, 능력치와 OVR을 확인할 수 있는 정적 웹앱입니다.

## 사이트
- **도감:** https://p0emkite.github.io/RKBO_Draft_and_CardArchive/
- **관리자:** https://p0emkite.github.io/RKBO_Draft_and_CardArchive/?admin=1
- GitHub Pages: Settings → Pages → Build and deployment: **Deploy from a branch** → **main** / **/(root)** → Save

## 포함된 기능
- 브론즈·실버·골드·코랄·다이아몬드 카드
- 8개 구단·타자/투수·포지션·등급별 필터, 선수 이름 검색, 정렬
- 즐겨찾기, 선수별 카드 상세 기록과 능력치
- 타자/투수 실루엣 기본 이미지 및 선수별 업로드 이미지
- **제작자 모드:** 관리자 전용 사진 업로드, 드래그 위치 조절, 휠 확대·축소, GitHub에 저장/동기화
- 시즌/HHRecord 자료 **첨부 및 원본 보관** (업로드한 다른 시즌의 자동 카드 생성은 아직 미구현)

- `enhancements.js`: 사진/관리자 기능, **`p0emkite/RKBO_Draft_and_CardArchive`의 `main` 브랜치**로 저장

## 선수 이름 표시
- 통산 제작기의 `data/player_db.csv` 사본을 `data/player_db.csv`에 보관합니다.
- `player-name-map.js`는 통산 제작기 `roster.js`의 이름 정규화·영문 순서 변형·중복 이름 검증 방식을 사용합니다.
- 카드 도감, 선수 상세, 관리자 사진 편집, 750×1050 PNG는 같은 한글 표시 이름을 사용합니다. 영문 이름과 원본 `rawName` 검색도 가능합니다.
- **현재 60차 시즌 211명 중 199명 매칭, 12명 미등록**. 미등록은 잘못된 이름을 추정하지 않고 원문 그대로 표시합니다.
- 새 선수 이름이 필요하면 이 저장소의 `data/player_db.csv`에 `Season,Team,Name,KoreanName` 양식으로 추가한 뒤 페이지를 새로고침하면 됩니다. 통산 제작기 원본 저장소는 수정되지 않습니다.


## 다중 시즌 도감 (2026-10 업데이트)

도감 상단의 **시즌 선택**에서 GitHub에 공개된 카드 데이터가 있는 시즌만 선택할 수 있습니다.

- \`60차 시즌\`은 기본으로 포함되어 있습니다. 60차 원본 카드 211장과 기존 OVR은 그대로 유지합니다.
- 다른 시즌은 **관리자 모드 → 시즌 카드 등록·공개**에서 시즌 번호 및 카드 데이터 JSON을 선택한 뒤 GitHub에 저장합니다.
- 관리자 등록 과정에서 카드 JSON을 검증하고 \`data/seasons/{회차}.json\` 파일이 정상 업로드된 이후 \`data/seasons.json\`에 시즌을 추가합니다. 시즌 목록에는 이 파일에 공개된 시즌만 나타납니다.
- 시즌 선택 시 카드·등급 수량, 선수 목록, 검색/필터, 카드 상세, PNG 저장 대상, 시즌 제목과 배경 시즌 번호가 함께 변경됩니다. 저장된 개인 사진 정보는 시즌별 카드 ID로 연결됩니다.
- \`data/player_db.csv\`의 한글 매칭을 추가 시즌에도 적용합니다. 원문 이름으로도 검색할 수 있습니다.

**중요:** 관리자 메뉴의 *시즌·HHRecord 자료 첨부* 기능은 원본을 GitHub에 백업하는 메뉴입니다. HTML/XLS/ZIP/HHRecord 파일만 업로드해도 카드 스탯·OVR을 계산하거나 시즌 목록에 자동 등록하지는 않습니다. 현재 공개 등록 기능은 **카드 스탯과 OVR이 준비된 JSON 파일**에 대해서만 지원합니다. 원본 → JSON 자동 변환기는 후속 개발 대상입니다.

## 시즌별 닉네임 표시

카드 도감은 **해당 시즌에 실제 사용한 닉네임**을 통산 통합 이름보다 우선합니다.

- `data/player_db.csv`: 통산 제작기 복사본, 기본 한글 음역과 시즌/구단 우선 매칭
- `data/season-nicknames.csv`: 시즌·구단·카드 ID별 별도 과거 닉네임 (최우선)
- `54-NC-투-009`: 기존 통산화된 `Fukutomi , Tsuki` 대신 `Pham , Hanni` → **하니**로 표시. HHRecord에서 Hanni Pham의 과거 활동 사실은 확인되지만 **54차까지 활동 시점은 사용자 회상에 따른 임시 설정**임.
- 그 밖의 시즌은 확인되지 않은 활동명을 추측하지 않고 기존 이름을 유지합니다. 다른 시즌의 사용명이 확인되면 CSV에 한 행을 추가하면 됩니다.
- 검색은 당시 한글/영문 이름과 통산 영문 이름을 모두 지원합니다. ID·스탯·OVR·등급·사진 링크는 보존합니다.


## 팀/닉네임 원본 우선순위 (54차 대조)
- RKBO 통합 엑셀은 선수별 스탯과 OVR 계산의 기준이며, 구단·당시 이름은 **해당 시즌 개인 성적표(TXT/HTML)**를 우선합니다.
- 54차 8개 구단 1군 208명을 주요 성적(G, AB, H, HR / G, GS, W, L, IP, K, BB, H, ER)으로 1:1 매칭했습니다.
- 54차 `Porter , Gaddo` (`54-LOT-투-001`)은 실제 소속 구단이 LG로 확인되어 팀·심볼만 LG로 변경했습니다. 기존 카드 고유 ID는 사진·관심카드 연결을 위해 고정하며, `excelTeam: LOT`은 감사 추적용입니다.
- 54차 8명의 시즌 원본 닉네임은 `seasonRecordedName`에 저장됩니다. 이름 우선순위는 수동 검증 별칭 → 시즌 개인 성적표 당시 이름 → 통산 엑셀 한글 매칭입니다.
- `data/seasons/54.json` 원본 스탯·OVR·능력치·등급은 변경하지 않습니다.

## 시즌 당시 팀과 닉네임 대조 (TXT/HTML)
- 기록·능력치·OVR: 통합 엑셀 우선. 당시 이름과 **소속팀**: 그 시즌 **1군 개인 성적표** 우선.
- **제작자 모드 → 당시 개인 성적표로 닉네임·소속팀 정정**에서 해당 시즌(1~59)을 고르고 구단별 TXT/HTML 또는 ZIP을 선택합니다.
- **당시 닉네임·소속팀 비교**를 누르면 이름이 달라도 G·AB·H·HR·RBI·BB·K(타자) 또는 G·GS·W·L·IP·K·BB·H·ER(투수)로 같은 선수를 판별합니다. 소속팀은 후보 탐색에 사용하지 않으므로 잘못된 엑셀 팀도 교정됩니다.
- 1:1 성적이 확실히 일치한 선수만 변경하며, 미일치·중복 후보는 검토 대상으로 남깁니다.
- **GitHub에 적용 · 원본 보관**에서 카드 JSON, 시즌 목록, 원본 ZIP/TXT, 업로드 목록을 한 번에 커밋합니다. 선수 고유 ID는 사진·즐겨찾기 보존을 위해 유지합니다.
- 원본이 검증된 시즌은 `data/seasons.json`의 `identityVerified:true`로 보호해 추후 엑셀 전체 재등록 시 이전 팀으로 되돌아가지 않게 합니다.
- 54차는 8개 구단 TXT에서 **208/208명 일치, 이름 8명 다름, 구단 1명 다름**을 확인했습니다. `Porter , Gaddo`의 표기 팀은 LG가 맞습니다. 엑셀 기록은 원본 추적을 위해 보존합니다.

## 시즌별 구단 브랜딩·원본 사진 처리

- **성적/고유 ID용 팀코드와 화면의 구단 브랜딩을 분리합니다.** 선수의 `team`, `id`, `stats`, `ratings`, `ovr`는 변경하지 않습니다.
- `team-branding.js`에서 `SSG` 코드는 **1~42차 카드에 SK 와이번스 / SK.svg**, 43차부터 SSG 랜더스 / SSG.svg로 표시합니다.
- `KIW`는 키움 히어로즈 / KIW.svg, `KT`는 KT 위즈 / KT.svg를 사용합니다. 로고 3개는 사용자가 제공한 파일입니다.
- 시즌 변경 시 카드 로고, 구단 이름, 팀 워터마크, 팀 검색 필터, 상세 정보, **750×1050 PNG**까지 함께 변경됩니다.
- 개인 성적표 업로드에서도 `SK.txt`·`SK.html`을 읽고 통합 엑셀의 `SSG`와 매칭할 수 있습니다.
- 사진 등록시 **원본 전체 보기(잘림 없음)**가 기본입니다. 필요할 때 편집기의 **영역 채우기(일부 잘림)**를 선택할 수 있습니다.
- 저장되는 `data/card-images.json`에는 사진 위치 `x/y`, 확대 `zoom`과 표시 방식 `fit=contain|cover`를 기록합니다. 기존 `fit` 없는 사진도 안전하게 `contain`으로 표시됩니다.
- 실제 카드·실시간 편집 미리보기·PNG 출력은 같은 표시 방식을 사용합니다.


## GitHub 사진 저장 후 빈 카드 방지
- 사진을 GitHub Contents API에 먼저 업로드하고 응답의 이미지 커밋 SHA를 `data/card-images.json`에 함께 기록합니다.
- 공개 카드 이미지는 신규 커밋의 `raw.githubusercontent.com` 주소를 사용하므로 Pages 배포 지연으로 인한 일시적 404를 피합니다. 실패하면 GitHub Pages 이미지 주소를 재시도하고, 최종적으로는 빈 화면 대신 실루엣을 표시합니다.
- 관리자 저장 직후에는 실제 공개 사진 주소가 로드됐다는 확인이 있기 전까지 브라우저에 있던 원본 미리보기(blob)를 **해제하지 않고 유지**합니다. 확인 후 자동 전환합니다.
- 일반 도감 방문자는 GitHub 공개 메타데이터를 우선 읽고, Pages 경로를 보조 경로로 사용합니다.
- 기존 `54-NC-투-009`의 사진 저장 커밋 `9829c489...`을 설정에 기록하여 이미 업로드된 파일을 다시 올리지 않고 복구합니다. 저장된 확대율·좌표는 변경하지 않습니다.

## 2026-10: 공개 사진 로딩 일관성 수정
- 관리자와 일반 방문자가 모두 **동일한 GitHub 최신 `data/card-images.json`**을 보도록, 일반 도감은 인증이 필요 없는 GitHub Contents API를 우선 조회합니다. 로그인 토큰이나 관리자 권한은 사용하지 않습니다.
- raw 이미지 CDN이 아직 업로드를 반영하지 않았다면 공개 Git Blob API에서 이미지 바이너리를 조회합니다. GitHub API 실패 시 Pages 이미지 경로를 다시 시도합니다.
- 각 카드의 업로드 응답 `content.sha`를 `blobSha`로 보관하며, 기존 하니(54차)와 웬디(60차)의 이미지 파일에도 해당 원본 SHA를 추가했습니다.
- 이미 저장된 사진 좌표, 확대율, OVR, 선수 고유 ID는 변경하지 않습니다.


## 카드 이름/포지션 레이아웃 및 구단 공통 배경 (2026-10-24)

- 카드 아트 아래 정보 영역은 **왼쪽 선수 이름 · 오른쪽 포지션** 한 줄로 표시합니다. 기존 구단명·유형 보조 텍스트는 카드 앞면에서 제거합니다. 선수 상세창과 기록·필터 기능은 유지합니다.
- 도감 카드와 저장하는 **750×1050 PNG**에 동일한 레이아웃을 적용합니다.
- 제작자 모드의 **▧ 구단 배경 편집** 메뉴에서 팀별 공통 이미지(16MB 이하)를 업로드하고, 확대·가로·세로 위치를 조정하며 실시간 미리보기할 수 있습니다.
- **도감에 즉시 적용**은 해당 브라우저 미리보기이며, **GitHub에 구단 배경 저장**을 누르면 `assets/team-backgrounds/{TEAM}.webp`와 `data/team-backgrounds.json`에 저장되어 일반 방문자에게도 공개됩니다.
- 등록한 구단 배경은 해당 팀의 **모든 시즌 카드**의 선수 이미지 아래에 표시됩니다. 선수별 이미지와 스탯·OVR·즐겨찾기·고유 ID는 변경되지 않습니다. 선수별 원본 사진이 불투명하면 그 영역 뒤의 배경은 가려질 수 있으며, 배경 투명 이미지에서는 구단 배경이 노출됩니다.
- 기존 팀 매핑에 따라 SK 와이번스(1~42차)와 SSG 랜더스(43차~)는 다른 배경 설정을 사용합니다. 삼성 등의 다른 팀은 시즌 구분 없이 같은 배경을 사용합니다.
